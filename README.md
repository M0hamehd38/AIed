# کلاس‌یار — دستیار هوشمند آموزش

پلتفرمی برای استاد دانشگاه: دیدن تسلط دانشجویان روی مفاهیم درس از روی آزمونک‌های کلاس، با پیشنهادهای آموزشی مبتنی بر شواهد که فقط با تأیید استاد اجرا می‌شوند.

## وضعیت: فاز ۲ (جلسه‌ی زنده)

آنچه کار می‌کند:

- **صفحه‌ی ابتدایی** با حرکت دوربین روی اسکرول، و ورود/ثبت‌نام واقعی (رمز با Argon2، محافظت CSRF، محدودیت تلاش ناموفق ورود).
- **پنل استاد**، با همان طراحی پروتوتایپ و حالت روز/شب:
  - نمای کلی
  - دانشجویان و نمایه‌ی هر دانشجو
  - تحلیل یادگیری
  - پیشنهادهای هوشمند، با تأیید، رد، ویرایش، لاگ ممیزی و ساخت پیش‌نویس سؤال
  - درس‌ها و جلسات، با چند درس برای هر استاد، افزودن مفهوم، جلسه و سؤال، و ورود دانشجو از CSV
  - تنظیمات آستانه‌ها برای هر درس
- **شواهد هر عدد** (سؤال‌ها، n و بازه‌ی اطمینان) با یک کلیک دیده می‌شود. زیر حداقل n، به‌جای نتیجه «داده کافی نیست» نمایش داده می‌شود.
- **نقش‌ها:** استاد فقط درس‌های خودش را می‌بیند. دانشجو به پنل استاد دسترسی ندارد. مدیر از `/admin` وارد می‌شود.
- **جلسه‌ی زنده** (فاز ۲):
  - استاد جلسه را شروع می‌کند و یک کد ۶ رقمی و QR می‌گیرد.
  - دانشجو با گوشی وارد `/j/` می‌شود و کد و شماره‌ی دانشجویی را می‌زند؛ رمز لازم نیست.
  - استاد مبحث و سپس سؤال را انتخاب و «پرسیدن» را می‌زند. سؤال در کمتر از نیم ثانیه روی گوشی‌ها می‌آید.
  - استاد می‌تواند سؤال را متوقف کند، ادامه دهد یا ببندد؛ دانشجو تا بسته‌شدن سؤال می‌تواند پاسخش را تغییر دهد.
  - توزیع پاسخ‌ها و برداشت فوری («بدفهمی احتمالی» یا «داده کافی نیست») لحظه‌ای فقط برای استاد نمایش داده می‌شود.
  - دانشجو فقط سؤال و پاسخ خودش را می‌بیند؛ گزینه‌ی درست و پاسخ دیگران برایش فرستاده نمی‌شود.
  - پاسخ‌ها همان لحظه ذخیره می‌شوند و در نقشه‌ی تسلط و همه‌ی تحلیل‌ها حساب می‌شوند.
  - با پایان جلسه کد باطل می‌شود. اگر اتصال لحظه‌ای قطع شود، صفحه‌ها هر چند ثانیه وضعیت را می‌پرسند تا اتصال برگردد.
- **ورود استاد** تا زدن «خروج» یا ۲ ساعت بی‌استفاده‌ماندن باقی می‌ماند.

آنچه هنوز پوسته است:

- **شنود صوت** (Whisper) در فاز ۳ کامل می‌شود.

نقشه‌ی مسیر کامل پروژه (فازهای بعد، معیار پایان هر فاز و تصمیم‌های باز): [`docs/ROADMAP.md`](docs/ROADMAP.md)

## ساختار

| مسیر | محتوا |
|---|---|
| `config/` | تنظیمات Django (همه از متغیرهای محیطی) |
| `apps/accounts` | کاربر با ایمیل و نقش (استاد، دانشجو، مدیر آموزش)، ورود و ثبت‌نام |
| `apps/courses` | درس، مفهوم، جلسه، سؤال، پاسخ، و فرمان `seed_demo` |
| `apps/insights` | تنظیمات هر درس، پیشنهادها و تصمیم‌ها، اتصال داده به تحلیل |
| `apps/audit` | لاگ ممیزی (چه کسی، چه زمانی، چه تصمیمی) |
| `apps/audio` | مدل‌های رضایت‌نامه و رونوشت (برای فاز ۳) |
| `apps/panel` | نماها، نمودارهای SVG سمت سرور، متن‌های فارسی پنل (`strings.py`) |
| `lib/analytics` | تحلیل خالص پایتون: Wilson، تسلط، تحلیل سؤال، هشدارها، قواعد پیشنهاد |
| `templates/`، `static/` | قالب‌ها، CSS، JS، تصویرها و فونت ساحل |
| `seed/prototype_data.json` | داده‌ی نمایشی، همان اعداد پروتوتایپ |
| `prototype/` | نسخه‌ی ایستای قبلی (`index.html` و `panel.html`) برای مقایسه |

## اجرا بدون Docker

```
pip install -r requirements-dev.txt
python manage.py migrate
DEMO_TEACHER_PASSWORD='رمز دلخواه' python manage.py seed_demo
python manage.py runserver
```

سپس `http://127.0.0.1:8000` را باز کنید و با `golzari@classyar.ir` و همان رمز وارد شوید.

- بدون `DATABASE_URL` از SQLite استفاده می‌شود.
- برای امتحان جلسه‌ی زنده با گوشی‌های واقعی در همان شبکه‌ی Wi-Fi:
  - سرور را با `python manage.py runserver 0.0.0.0:8000` اجرا کنید.
  - نشانی IP کامپیوتر را به `DJANGO_ALLOWED_HOSTS` اضافه کنید، مثلاً `DJANGO_ALLOWED_HOSTS=localhost,127.0.0.1,192.168.1.20`.
  - دانشجوها QR روی صفحه‌ی استاد را اسکن می‌کنند.
- رمز استاد نمایشی هیچ‌جا در کد نیست و فقط از `DEMO_TEACHER_PASSWORD` خوانده می‌شود.
- برای بارگذاری دوباره‌ی داده‌ی نمایشی، `seed_demo --reset` را اجرا کنید.
- برای ساخت حساب مدیر، `python manage.py createsuperuser` را اجرا کنید.

## اجرا با Docker

```
cp .env.example .env    # مقادیر را پر کنید
docker compose up --build
```

- سرویس‌ها: وب (Daphne، که هم صفحه‌ها و هم WebSocket جلسه‌ی زنده را سرویس می‌دهد)، PostgreSQL و Redis.
- Redis به‌روزرسانی‌های لحظه‌ای را بین پردازه‌های سرور جابه‌جا می‌کند. بدون `REDIS_URL` (در توسعه) همه‌چیز در حافظه‌ی یک پردازه است.
- پشت پراکسی (مثلاً nginx) مسیر `/ws/` را با هدرهای Upgrade و Connection به وب بفرستید تا WebSocket کار کند.
- هنگام شروع، migrate اجرا می‌شود. اگر `DEMO_TEACHER_PASSWORD` پر باشد، داده‌ی نمایشی هم بارگذاری می‌شود.
- برای اجرای محلی روی http، مقدار `DJANGO_SSL_REDIRECT=0` لازم است. پشت https آن را حذف کنید تا کوکی‌ها فقط-https و HSTS فعال شوند.

## آزمون‌ها

```
pytest
```

- ۶۷ آزمون، شامل:
  - اعداد تحلیل که باید دقیقاً با پروتوتایپ یکی باشند (مرجع: `tests/fixtures/prototype_reference.json`).
  - ورود و ثبت‌نام و محدودیت تلاش.
  - جداسازی داده‌ی استادها.
  - ثبت تصمیم‌ها در لاگ ممیزی.
  - تنظیمات و پنهان‌کردن نام‌ها.
  - ساخت درس، جلسه، سؤال و ورود CSV.
  - جلسه‌ی زنده: شروع و پایان، ورود دانشجو و محدودیت تلاش، پاسخ‌دادن و تغییر پاسخ، مکث و بستن، پاسخ ۳۰ دانشجو، حریم خصوصی، و WebSocket استاد و دانشجو.
- عدد نمونه: در «مبانی برنامه‌نویسی» ۱۲ دانشجو نیازمند پیگیری‌اند.

## اصول

- **تصمیم با استاد است:** هر پیشنهاد پیش‌نویس است تا استاد تأیید کند، و هر تصمیم در لاگ ممیزی ثبت می‌شود.
- **شواهد پیش از برچسب:** هر عدد همراه n و میزان اطمینان آمده است.
- **درباره‌ی مفهوم، نه شخص:** متن‌ها از «مفهوم دشوار» حرف می‌زنند.
- **حریم خصوصی از روز اول:**
  - در لاگ‌ها داده‌ی شخصی ثبت نمی‌شود.
  - نمایش نام دانشجو قابل خاموش‌کردن است.
  - صدای خام هرگز ذخیره نمی‌شود.

## فونت

- فونت نوشته‌ها **Digi Rastin Plus** (نسخه‌ی Circle) از DigiFonts است.
- این فونت تجاری است و چون این مخزن عمومی است، فایل آن در گیت نیست.
- برای اجرا، فایل `DigiRastinPlus-Circle.woff2` را در `static/fonts/` بگذارید.
- اگر فایل نباشد، صفحه‌ها خودکار با فونت ساحل نمایش داده می‌شوند.
- برای استفاده‌ی عمومی روی وب، مجوز وب این فونت را از DigiFonts بگیرید.
